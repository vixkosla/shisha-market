На сервере флаг не включали и окружение не меняли. Избранное объявлений сохраняется.

Внутреннего чата покупателя с продавцом нет. В настоящем одобренном объявлении кнопка «Связаться с продавцом» открывает указанную автором HTTPS-ссылку на профиль Telegram (`t.me`) или ВК (`vk.ru`, `vk.com`), доступную и посетителю без входа. У демонстрационных карточек такой кнопки нет. Договорённости и переписка происходят вне площадки; форма поддержки предназначена для обращений к администрации, а не для диалога сторон сделки.


[Юридическая основа пилота](docs/LEGAL_BASELINE.md) от 8 октября: границы модели, источники, инструкция по обращениям и условия допуска к реальным аккаунтам. Тексты согласий и их версия этой технической настройкой не меняются.

## Локальный запуск

Нужен Node.js 22. Из этой папки:

```bash
npm ci
npm run dev
```

Открыть http://127.0.0.1:4387. Сервер доступен только с этого компьютера. Docker, внешний PostgreSQL и аккаунты облачных сервисов для разработки не нужны.

По умолчанию используется PGlite, локальная PostgreSQL-совместимая база в `.data/postgres`. Миграции применяются при первом обращении. Фотографии сохраняются в `.data/uploads`. Эти данные исключены из Git. PGlite разрешён только для разработки; одновременно открывать его каталог из нескольких процессов нельзя.

В текущей локальной `.env.local` задано `AUTH_ENABLED=false`, поэтому форма входа закрыта. Только для проверки на синтетических аккаунтах можно запустить `AUTH_ENABLED=true npm run dev`: на странице входа введите тестовую почту, одноразовый код появится в терминале сервера. Реальные письма в этом режиме не отправляются. Секрет сессий генерируется в памяти; перезапуск завершает существующие сессии. Для постоянных сессий задайте `BETTER_AUTH_SECRET` длиной не менее 32 символов в `.env.local`. Список настроек — в `.env.example`.

Чтобы назначить модератора, сначала войдите в приложение с нужной почтой, остановите локальный сервер и выполните:

```bash
npm run user:role -- your-address@example.com moderator
npm run dev
```

Роль задаётся только этой административной командой. Регистрация не принимает роль от клиента. Для PostgreSQL останавливать приложение перед командой не требуется.

## Что реализовано

- Каталог с категориями, городом, полнотекстовым поиском на русском и постраничной выдачей.
- Вход по одноразовому коду через Better Auth с возвратом к созданию/редактированию и отсчётом повторных попыток; конфигурация провайдера VK ID.
- Создание объявления с 1–6 фотографиями, предпросмотром, выбором обложки, ценой, состоянием и ссылкой для связи. Восстанавливаемый текстовый черновик в этой вкладке не включает ФИО, контакт, согласия и фото.
- Редактирование собственных активных и отклонённых объявлений: сохранение/замена фото, новое согласие и повторная модерация. Устаревшие правки и решения модератора отклоняются по номеру версии; архивные объявления не восстанавливаются этой формой.
- Кабинет владельца, избранное и снятие объявления с публикации.
- Очередь модерации, одобрение и отклонение с причиной, журнал решений.
- Служебные уведомления о поступлении и результате проверки после ответа сервера; доставка best effort, основной статус — в кабинете. Копирование ссылки на опубликованную карточку.
- Служебный MCP: создание, очередь, чтение карточки/закрытых фото, правка своего объявления, человеческая модерация и снятие с сайта. Стандартный SDK проверяет реальное stdio-подключение; ключ оператора продавцам не выдаётся.
- Раздельные непредустановленные согласия при входе и публикации, серверная проверка версии, закрытый журнал текстов и условий согласия.
- Жалобы, обжалование, запросы о данных, ответы модератора и снятие публикации; отзыв согласия сразу скрывает собственные объявления. Полное удаление аккаунта пока выполняется отдельно вручную, не кнопкой закрытия обращения.
- Обработка JPG, PNG и WebP: проверка содержимого, ограничение размера и разрешения, нормализация в WebP и удаление метаданных.
- Отдельные хранилища для разработки и S3; фотографии выдаются через сервер с проверкой доступа.
- Автопубликация одобренных объявлений в сообществе ВК (фото, название, цена, город и ссылка). Включается парой `VK_GROUP_TOKEN`/`VK_GROUP_ID`; без них посты не уходят.
- Английский каркас `/en` (главная, каталог, MCP и пять юридических документов) и машиночитаемые ресурсы для ИИ-агентов: `llms.txt`, `llms-full.txt`, `/ai/status`.

Объявление создаётся в состоянии `pending`. Модератор переводит его в `published` или `rejected`; владелец может перевести своё объявление в `archived`. Публичный каталог показывает только `published`. Остальные объявления и фотографии видят только владелец и модераторы. Повторное решение модератора отклоняется, изменение статуса и запись журнала выполняются в одной транзакции.

Категории в тестовом интерфейсе — кальяны, чаши и аксессуары; это не юридический допуск. В production категории и страны закрыты до явного заполнения проверенной матрицы. Нет оплаты, доставки, внутреннего чата и блокировки аккаунтов. Служебный MCP умеет создавать объявление на сайте; в паблик ВК оно уходит автоматически, если на сервере включена автопубликация ключом сообщества. Инструкция для оператора — на служебной странице `/mcp/operator`, оттуда же скачивается клиент `listings.mjs`. Интерфейс — стартовый вариант, не восстановленная копия старого дизайна. Публичный запуск и индексация требуют отдельной приёмки.

## Структура

| Путь                      | Назначение                                          |
| ------------------------- | --------------------------------------------------- |
| `src/app`                 | Страницы, серверные действия, HTTP маршруты         |

| `src/server/db/schema.ts` | Схема таблиц и индексы                       |

| `src/server/vk.ts`        | Автопубликация одобренных объявлений в ВК           |
| `src/server/legal-policy.ts` | Допуск production, стран и категорий; публичные реквизиты |
| `src/server/legal-documents.ts` | Версионируемые тексты правил и согласий |
| `src/server/support.ts` | Закрытые обращения, ответы и снятие публикаций |
| `src/lib/listings.ts`     | Валидация, деньги в копейках и правила чтения       |

| `tests`                   | Модульные, интеграционные и браузерные проверки     |

После изменения схемы выполните `npm run db:generate`, проверьте SQL и затем `npm run db:migrate` для PostgreSQL. Не используйте автоматический `push` схемы в рабочую базу.

## Подключение внешних сервисов

Для размещения требуется PostgreSQL, закрытый S3 bucket и SMTP. В `.env.production` задайте `APP_URL` с HTTPS, случайный `BETTER_AUTH_SECRET`, параметры SMTP и S3 из примера. В `.env` для Docker Compose задайте `POSTGRES_PASSWORD` и `SITE_HOST`. Используйте случайный hex-пароль, чтобы не требовалось кодировать специальные символы в URL подключения.

```bash
docker compose --profile deploy up --build -d
```

Compose — альтернативный шаблон: он поднимает PostgreSQL, применяет миграции отдельной задачей, запускает приложение и Caddy с HTTPS. Порт базы привязан только к loopback. Контейнерный вариант требует отдельной проверки. На существующем VPS фактически используются systemd, PostgreSQL, Garage S3 и Caddy без Docker, чтобы не вмешиваться в VPN firewall.

VK ID сейчас закрыт в коде, даже если настроены `VK_CLIENT_ID` и `VK_CLIENT_SECRET`: сначала нужна проверка переноса и фиксации согласия через OAuth и привязки аккаунта. Callback после реализации остаётся `<APP_URL>/api/auth/callback/vk`. Автоматическое объединение аккаунтов по совпадению почты отключено. Вход через VK ID не даёт приложению права публиковать записи в сообществе.

S3 bucket должен оставаться закрытым: приложение читает фотографии серверными ключами и проверяет статус объявления перед выдачей. Публичный ACL и `S3_PUBLIC_URL` не требуются. SMTP использует TLS. Режимы вывода кодов в консоль, локального файлового хранилища и PGlite запрещены в production.

OAuth-токены шифруются с использованием секрета приложения. VK запрашивает только доступ к почте для входа, без номера телефона. Смена `BETTER_AUTH_SECRET` требует планирования: она влияет не только на сессии, но и на чтение сохранённых OAuth-токенов.

## Перед публичным запуском

Production требует настоящих реквизитов и заполнения `LEGAL_DATA_LOCATION`, `LEGAL_PROCESSORS`, `LEGAL_RETENTION`, `LEGAL_APPROVED_MARKETS`; после организационной проверки владелец подтверждает `LEGAL_PUBLIC_READY=true`. Пустая или некорректная матрица не открывает категории. Флаг не является юридическим разрешением. Подробности и публичные поля — в `.env.example` и юридической основе. В локальной разработке используются только синтетические данные; нельзя выставлять development-сервер наружу вместо выполнения условий запуска.

Перед серверным выпуском примените все ещё не применённые миграции, включая `0001_pink_exodus.sql`, `0002_suggestions.sql` и `0003_listing_revisions.sql`, с резервной копией. На проде все три применены 19 октября 2026. Последняя добавляет номера версий объявлений и решений модерации; старые записи получают версию 1. Для уже запущенного локального PGlite перезапустите только принадлежащий этому проекту сервер, чтобы применились миграции. Не открывайте тот же каталог отдельным мигратором. Обновлённому служебному MCP нужен параметр `revision` из очереди; сервер и клиент выпускаются согласованно.

1. Проверить миграции и полный сценарий на серверном PostgreSQL, доставку писем и чтение из закрытого S3. VK callback и связь аккаунтов проверяются перед включением необязательного VK ID; они не должны блокировать запуск с работающим входом по почте.
2. Настроить регулярный вывоз резервных копий вне VPS и проверить полное восстановление S3. Ежедневные локальные копии PostgreSQL, Garage и секретов уже настроены; восстановление БД проверено, разовая копия сохранена на рабочем компьютере. Один VPS не обеспечивает репликацию и отказоустойчивость.
3. Добавить блокировки аккаунтов и защиту от массовых регистраций. Жалобы уже есть, но их очередь нужно проверять вручную. Для объявлений подключены best-effort письма модератору/автору; гарантированной фоновой очереди повторов пока нет. Ограничитель авторизации сейчас работает в памяти одного процесса.
4. Утвердить допустимые категории, реквизиты, размещение, сроки и процедуры обработки данных, необходимые уведомления и исполнение запросов на удаление. Тексты страниц и согласий не заменяют эти действия.
5. Настроить домен, мониторинг ошибок, SEO и sitemap; снять запрет индексации после проверки публикаций.

Использованная документация: [Next.js](https://nextjs.org/docs/app), [Drizzle](https://orm.drizzle.team/docs/overview), [Better Auth и Next.js](https://better-auth.com/docs/integrations/next), [VK ID](https://better-auth.com/docs/authentication/vk). Фиксированные версии установлены в `package-lock.json`.
